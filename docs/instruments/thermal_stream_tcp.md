# 热流仪 TCP 接口能力与接入说明

更新日期：2026-09-13。本文用于 Unicorn Testbench 的热流仪驱动开发、联调和自动温度测试。

当前实机的 PC 通信入口为 **`192.168.1.50:3000`，Modbus TCP，Unit ID 为 `0`**。
已经通过 TCP 读取空气温度、产品温度和运行状态，验证 R105 写入 -25℃及 -40℃、R103 写入 125℃、
C16 关闭低温、C14 打开高温、C0 启动及 C1 停止命令。
9 月 11 日的 -25℃记录未观察到有效降温；125℃测试已观察到实际升温。
9 月 13 日的 -40℃测试在启动约 57 秒后进入目标 ±1℃，但随后发生连接重置，
三阶段测试中断；恢复连接后发送 C1 并确认 C10=0。完整结果见文末记录。
其他设温、流量、其他模式切换、程式和除霜等写操作仍未进行实机验证。

本文以厂家 TCP 协议为功能依据，以现场面板信息和实际收发报文记录实机情况。
存在矛盾的地址保留两种原始表述，不将候选地址写成已确认的接口。

## 协议与编码

### 地址和功能码

以下地址默认为十进制，`0x` 前缀表示十六进制；`C` 表示线圈，`R` 表示 16 位寄存器。
例如 `C0` 是启动命令位，`R0` 是空气温度，它们属于不同地址空间。
报文中的地址是从 `0` 开始的原始协议地址，不额外加 `1`，也不拼接 `40001` 等显示编号。

| 功能码 | 操作 | TCP 文档和验证情况 |
| --- | --- | --- |
| `0x01` | 读取线圈 | 单独读取 C10、C14 至 C22、C24、C25 已验证 |
| `0x03` | 读取寄存器 | R0 至 R4、R14 至 R16、R102 至 R107、R109 至 R112、R124 至 R126 已有单寄存器读取响应；候选地址和单位歧义仍保留 |
| `0x05` | 写单个线圈 | C0/C1 写 ON 并读 C10 确认启停、C16 写 OFF 和 C14 写 ON 已验证；其他写入未验证 |
| `0x06` | 写单个寄存器 | R103 写 125℃及 R105 写 -25℃、-40℃并读回已验证；其他写入未验证 |
| `0x0F` | 写多个线圈 | TCP 功能码表列出，未提供详细 TCP 示例，未实测 |
| `0x10` | 写多个寄存器 | 仅 485 手册提供说明，不能据此确认 TCP 支持 |

TCP 文档对 `0x06` 的摘要写有“一个或多个存储器”，但其具体报文只有单个地址和单个值；
按单寄存器写操作理解。多寄存器写入不能套用 `0x06`。

### TCP 报文

报文为二进制字节：`7 字节 MBAP 头 + 功能码 + 数据`，不追加 RTU CRC。
文档中连续的十六进制字符串表示字节序列，不是应直接发送的 ASCII 文本。

| 字段 | 字节数 | 内容 |
| --- | --- | --- |
| Transaction ID | 2 | 请求和响应配对；当前脚本为 `0x0000` |
| Protocol ID | 2 | `0x0000` |
| Length | 2 | 后续字节总数，包含 Unit ID 和 PDU |
| Unit ID | 1 | 当前设备使用 `0x00` |
| Function | 1 | 例如 `0x03` |
| Data | 可变 | 地址、数量、数值或返回数据 |

多字节字段按高字节在前编码。读取一个寄存器时，请求的 Length 为 `6`，正常响应为 `5`；
读取一个线圈时，请求的 Length 为 `6`，正常响应为 `4`。
厂家概述表的“固定码”省略了单独的 Unit ID 列，完整地址表示例和实测均包含它。
不要遗漏 Unit ID，也不要把 Length 永久写死为 `6`。

TCP 可能分段返回数据。当前脚本先收齐 7 字节头，再按 Length 收齐剩余 `Length - 1` 字节，
检查事务号、协议号、Unit ID、功能码和数据字节数。异常响应的功能码为请求功能码加 `0x80`，
后跟异常码；当前脚本能识别此格式，但实机尚未返回过异常响应。
通用帧结构参考 [Modbus TCP 实施指南第 3.1 节](https://www.modbus.org/file/secure/messagingimplementationguide.pdf)，
功能码和异常格式参考 [Modbus 应用协议规范](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)。

### 数值单位

| 数据 | 编码规则 | 依据和限制 |
| --- | --- | --- |
| 温度 | 16 位有符号整数，数值为温度乘以 `10` | 正负温读取，以及 R105 的 -25℃ 编码 `0xFF06`、-40℃ 编码 `0xFE70` 写入读回已验证；未做独立传感器校准 |
| 线圈写 ON | `0xFF00` | `0x05` 的厂家写入示例 |
| 线圈写 OFF | `0x0000` | `0x05` 的厂家写入示例 |
| 单个线圈读值 | 返回数据字节的最低位 | `C10=0/1` 已验证；多线圈读取未测试 |
| 流量设定 | `R106`、`R107` 的示例按流量乘以 `10`，单位 SCFM | 例如 8.0 SCFM 对应 80；写入未验证 |
| 实际流量 `R102` | 文档未明确给出缩放 | 不能仅因设定值乘以 10 就将实际流量换算视为已确认 |
| 温度出力、流量出力 | 原始寄存器值 | 文档未给出百分比等明确单位 |
| 运行时间 | 按字段标注的 H、M、S | 不同字段单位不同，见地址表 |
| 温度斜率 `R126` | 示例“5度”对应 50 | 时间基准未说明，不能直接标为 ℃/min |

温度编码示例：`85.0℃ -> 850 -> 0x0352`；`25.0℃ -> 250 -> 0x00FA`；
`-40.0℃ -> -400 -> 0xFE70`。读取原始值 `u` 时，可用
`signed = u if u < 32768 else u - 65536`，再计算 `signed / 10`。
这些数值是编码示例，不代表设备温度上下限；实际限值和允许精度应与设备配置核对。

例如“高温运行时间”表格写地址 12，但写 10 秒的调试码中地址为 `00 0B`，即十进制 11。

## 温度测试的接入流程

下面是上位机开发的工程流程。低温测试接续设备已有的运行；高温测试从停止状态执行
R103 设值、C16=0、C14=1、C0 启动，并通过各项读回及实际温升确认此路径有效。

1. 建立连接，读取 R0、R1、C10，并与面板核对。
2. 根据测试方案选择定值或程式模式、定时方式以及空气或产品温度控制。
3. 写入所选模式对应的目标温度；需要调整流量时再设置 R107，并读回设定值。
4. 先关闭其他温度模式，再打开所选模式，整体读回核对后触发启动。C17 至 C19 只读记录；本机低温切高温时标志自动变化。
5. 轮询实际温度和运行状态；按测试方案定义的温差带和持续时间判断稳定，再执行电测。
6. 执行下一温度点，或发送停止并确认 C10 回到 0。

C10 只表示运行或停止，不表示到温。TCP 文档没有提供已确认的“产品温度稳定”判据；
不能把 485 手册里的“温度恒定信号”直接移植到 TCP 驱动。
R5 定义的是回常温温度参数，文档未给出单独的“立即回常温”命令地址。

驱动初期可沿用探测脚本的串行请求方式，在上一请求完成后再发下一请求。
读请求可在断线重连后重试；写请求超时时可能已经被设备执行，应先查状态或读回参数，
尤其是启动、跳段、翻页等动作，不应因没收到响应就直接重复执行。
这属于上位机的异常处理建议，设备的断线动作和看门狗机制尚无文档依据。

## 文档疑点与功能边界

| 问题 | 当前处理 |
| --- | --- |
| 厂家 IP `.55` 与实机 `.50` 不同 | 实机连接和面板均确认 `.50`；驱动将地址作为配置项 |
| 时间和循环字段的表格地址与报文地址不同 | 保留对照表；需要厂家确认或逐项比对，尚未修正为确定值 |
| 程式预计结束 H 标为双字，但只读一个寄存器 | 数据宽度、地址占用均待确认 |
| 程式链接表列 80，报文为 79 | 保留冲突，不向候选地址自动写入 |
| C26 读取示例的数量为 `0000` | 不复用该示例；读取一个位按协议应为 `0001`，设备响应未验证 |
| C17 至 C19 表列只读，但 485 手册末尾要求复位及置位 | TCP 侧按状态位记录；本机停止时 C16=0、C14=1 后，C19 自动变 0、C17 自动变 1。无需在已验证流程中写它们；其他流程未验证 |
| R124、R125 标注读写，但只有读例 | 写入格式及实际意义待确认 |
| TS1、TS2、待机未给完整含义 | 只记录名称、地址和示例值，不推断其控制效果 |
| 温度斜率没有时间单位；实际流量和出力缩放不全 | 保留原始值及未知单位，不直接换算为未确认的物理量 |
| 程式段数、编号范围、页面映射和数据保存机制不完整 | 不能仅按五段地址表推定完整程式容量和保存行为 |

485 手册另列 C32 至 C35 的温度趋势或控温对象信号，以及 R82、R83 的温度上升和下降偏差。
TCP 文档没有这些线圈定义，并将寄存器 81 至 101 列为备用；本说明不将它们算作已开放的 TCP 功能。

485 手册还列有 `WC 0, ON`、`R? 0, 1`、`W 103, 850` 等 SCPI 对应命令，
但未说明文本命令的独立端口、传输方式或结束符，不能据此向 TCP 3000 端口发送 SCPI 文本。
TCP 的 `0x10` 支持情况也不能从 485 手册直接推定。

三份参考资料中未找到完整的故障或报警码表、急停接口、直接 P/I/D 参数、型号或固件版本查询、
通信 IP 配置寄存器，以及断线后的设备动作定义。这表示当前资料不足，并不证明硬件不存在这些能力。
